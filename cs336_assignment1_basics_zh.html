2 字节对编码（BPE）分词器

作业的第一部分，我们将训练并实现一个字节级（byte-level）字节对编码（BPE）分词器 [R. Sennrich et al., 2016; C. Wang et al., 2019]。特别地，我们将把任意（Unicode）字符串表示为一个字节序列，并在这个字节序列上训练我们的 BPE 分词器。稍后，我们将使用该分词器将文本（字符串）编码为 token（整数序列），用于语言建模。

2.1 Unicode 标准

Unicode 是一种文本编码标准，它将字符映射到整数码点（code point）。截至 Unicode 17.0（2025 年 9 月发布），该标准定义了 172 种文字中的 159,801 个字符。例如，字符 "s" 的码点为 115（通常记作 U+0073，其中 U+ 是惯用前缀，0073 是 115 的十六进制表示），字符 "牛" 的码点为 29275。在 Python 中，你可以使用 ord() 函数将单个 Unicode 字符转换为它的整数表示。chr() 函数则将整数 Unicode 码点转换为包含相应字符的字符串。

>>> ord('牛')
29275
>>> chr(29275)
'牛'

2.2 Unicode 编码

虽然 Unicode 标准定义了从字符到码点（整数）的映射，但直接在 Unicode 码点上训练分词器并不实际，因为词汇表会大得令人望而却步（约 15 万项）且十分稀疏（因为许多字符相当罕见）。相反，我们将使用一种 Unicode 编码，它将 Unicode 字符转换为字节序列。Unicode 标准本身定义了三种编码：UTF-8、UTF-16 和 UTF-32，其中 UTF-8 是互联网上的主导编码（超过 98% 的网页使用它）。

要将 Unicode 字符串编码为 UTF-8，我们可以使用 Python 中的 encode() 函数。要访问 Python bytes 对象的底层字节值，我们可以对其进行迭代（例如调用 list()）。最后，我们可以使用 decode() 函数将 UTF-8 字节串解码为 Unicode 字符串。

>>> test_string = "hello! こんにちは!"
>>> utf8_encoded = test_string.encode("utf-8")
>>> print(utf8_encoded)
b'hello! \xe3\x81\x93\xe3\x82\x93\xe3\x81\xab\xe3\x81\xa1\xe3\x81\xaf!'
>>> print(type(utf8_encoded))
<class 'bytes'>
>>> # 获取编码后字符串的字节值（0 到 255 的整数）。
>>> list(utf8_encoded)
[104, 101, 108, 108, 111, 33, 32, 227, 129, 147, 130, 147, 227, 129, 171, 227, 129, 161, 227, 129, 175, 33]
>>> # 一个字节不一定对应一个 Unicode 字符！
>>> print(len(test_string))
13
>>> print(len(utf8_encoded))
23
>>> print(utf8_encoded.decode("utf-8"))
hello! こんにちは!

通过将 Unicode 码点转换为字节序列（例如通过 UTF-8 编码），我们本质上是在将一个码点序列（21 位整数，159,801 个有效值）转换为一个字节值序列（0 到 255 范围内的整数）。256 长度的字节词汇表要容易处理得多。使用字节级分词时，我们无需担心词表外（out-of-vocabulary）的 token，因为我们知道任何输入文本都可以表示为 0 到 255 的整数序列。

2.3 子词分词

虽然字节级分词可以缓解词级（word-level）分词器面临的词表外问题，但将文本分词为字节会产生极长的输入序列。这会拖慢模型训练，因为一个 10 个词的句子在词级语言模型中可能只有 10 个 token，但在字符级模型中可能有 50 个或更多 token（取决于词的长度）。处理这些更长的序列需要在模型的每一步进行更多计算。此外，在字节序列上进行语言建模很困难，因为更长的输入序列会在数据中产生长程依赖。

子词（subword）分词是词级分词器和字节级分词器之间的折中方案。注意，字节级分词器的词汇表有 256 项（字节值从 0 到 255）。子词分词器以更大的词汇表来换取对输入字节序列更好的压缩。例如，如果字节序列 b'the' 经常出现在我们的原始文本训练数据中，为它分配一个词汇表条目就能将这个 3-token 序列缩减为单个 token。

我们如何选择要加入词汇表的子词单元？[R. Sennrich et al. 3] 提出使用字节对编码（BPE；[P. Gage 5]），这是一种压缩算法，它迭代地将最频繁的字节对替换（「合并」）为一个新的、未使用的索引。注意，该算法向词汇表添加子词 token 以最大化对输入序列的压缩——如果一个词在输入文本中出现次数足够多，它就会被表示为一个单独的子词单元。

使用通过 BPE 构建的词汇表的子词分词器通常被称为 BPE 分词器。在本作业中，我们将实现一个字节级 BPE 分词器，其中词汇表项是字节或合并后的字节序列，这让我们在词表外处理和可控的输入序列长度两方面兼得好处。构建 BPE 分词器词汇表的过程被称为「训练」BPE 分词器。

2.4 BPE 分词器训练

BPE 分词器训练过程包括三个主要步骤。

词汇表初始化

分词器词汇表是从字节串 token 到整数 ID 的一一映射。由于我们训练的是字节级 BPE 分词器，初始词汇表就是所有字节的集合。由于有 256 种可能的字节值，我们的初始词汇表大小为 256。

预分词（Pre-tokenization）

有了词汇表之后，原则上你可以统计文本中字节彼此相邻出现的频率，并从最频繁的字节对开始合并。然而，这在计算上相当昂贵，因为每次合并我们都要对语料库完整遍历一遍。此外，直接在语料库上合并字节可能会产生仅在标点符号上不同的 token（例如 dog! 与 dog.）。这些 token 会得到完全不同的 token ID，尽管它们很可能具有很高的语义相似性（因为它们仅在标点上不同）。

为避免这一点，我们对语料库进行预分词。你可以把它理解为对语料库的一种粗粒度分词，帮助我们统计字符对出现的频率。例如，单词 'text' 可能是一个出现了 10 次的 pre-token。在这种情况下，当我们统计字符 't' 和 'e' 相邻出现的频率时，我们会看到单词 'text' 中 't' 和 'e' 相邻，因此可以将它们的计数加 10，而不必遍历语料库。由于我们训练的是字节级 BPE 模型，每个 pre-token 都表示为一个 UTF-8 字节序列。

[R. Sennrich et al. 3] 的原始 BPE 实现通过简单地在空白处切分来进行预分词（即 s.split(" ")）。这种方法仍然存在于基于 SentencePiece 的分词器中（例如 Llama 1 和 2 的分词器）。

大多数现代分词器使用基于正则表达式的预分词器，这一做法来自 GPT-2；[A. Radford et al. 6]。我们将使用该原始正则表达式的一个稍微更整洁的版本，取自 github.com/openai/tiktoken/pull/234/files：

>>> PAT = r"""'(?:[sdmt]|ll|ve|re)| ?\p{L}+| ?\p{N}+| ?[^\s\p{L}\p{N}]+|\s+(?!\S)|\s+"""

用这个预分词器交互式地切分一些文本，可能有助于你更好地理解它的行为：

>>> # 需要 `regex` 包
>>> import regex as re
>>> re.findall(PAT, "some text that i'll pre-tokenize")
['some', ' text', ' that', ' i', "'ll", ' pre', '-', 'tokenize']

不过，在你的代码中使用它时，你应该使用 re.finditer，以避免在构建从 pre-token 到其计数的映射时存储预分词后的单词。

计算 BPE 合并

现在我们已经把输入文本转换为 pre-token，并将每个 pre-token 表示为一个 UTF-8 字节序列，就可以计算 BPE 合并（即训练 BPE 分词器）了。从高层次上看，BPE 算法迭代地统计每个字节对，并识别出频率最高的字节对（"A", "B"）。这个最频繁字节对（"A", "B"）的每次出现随后被合并，即替换为一个新 token "AB"。这个新的合并 token 被加入词汇表；因此，BPE 训练后的最终词汇表大小为初始词汇表大小（我们的情况是 256）加上训练期间执行的 BPE 合并操作次数。为了提高 BPE 训练的效率，我们不考虑跨越 pre-token 边界的字节对。² 在计算合并时，通过对字节对频率的平局做确定性处理——优先选择字典序更大的字节对。例如，如果字节对（"A", "B"）、（"A", "C"）、（"B", "ZZ"）和（"BA", "A"）都具有最高频率，我们会合并（"BA", "A"）：

>>> max([("A", "B"), ("A", "C"), ("B", "ZZ"), ("BA", "A")])
('BA', 'A')
² 注意，R. Sennrich et al. [3] 的原始 BPE 公式指定要包含一个词尾（end-of-word）token。在训练字节级 BPE 模型时我们不添加词尾 token，因为所有字节（包括空白和标点）都已包含在模型的词汇表中。由于我们显式地表示空格和标点，学习到的 BPE 合并自然会反映这些词边界。
特殊 token

通常，一些字符串（例如 <|endoftext|>）被用来编码元数据（例如文档之间的边界）。在编码文本时，通常希望将某些字符串视为「特殊 token」，它们永远不应被拆分为多个 token（即始终作为单个 token 保留）。例如，序列结束字符串 <|endoftext|> 应始终作为单个 token（即单个整数 ID）保留，这样我们就能知道何时停止从语言模型生成。这些特殊 token 必须加入词汇表，从而拥有对应的固定 token ID。

[R. Sennrich et al. 3] 的算法 1 包含了一个低效的 BPE 分词器训练实现（本质上遵循我们上面概述的步骤）。作为第一个练习，实现并测试这个函数来检查你的理解可能会有所帮助。

示例（bpe_example）：BPE 训练示例

下面是一个来自 R. Sennrich et al. [3] 的风格化示例。考虑一个由以下文本组成的语料库：

low low low low low
lower lower widest widest widest
newest newest newest newest newest newest

且词汇表有一个特殊 token <|endoftext|>。

词汇表

我们用特殊 token <|endoftext|> 和 256 个字节值初始化词汇表。

预分词

为简单起见并聚焦于合并过程，我们在此示例中假设预分词只是在空白处切分。当我们进行预分词并计数时，我们得到如下频率表。

{low: 5, lower: 2, widest: 3, newest: 6}

把它表示为 dict[tuple[bytes, ...], int] 会很方便，例如 {(l,o,w): 5, ...}。注意，即使是单个字节，在 Python 中也是 bytes 对象。Python 中没有用来表示单个字节的 byte 类型，正如没有用来表示单个字符的 char 类型一样。

合并

我们首先查看每一对相邻字节，并求和它们出现的词的频率 {lo: 7, ow: 7, we: 8, er: 2, wi: 3, id: 3, de: 3, es: 9, st: 9, ne: 6, ew: 6}。字节对 ('e', 's') 和 ('s', 't') 频率相同，所以我们取字典序更大的字节对 ('s', 't')。然后我们合并 pre-token，得到 {(l,o,w): 5, (l,o,w,e,r): 2, (w,i,d,e,st): 3, (n,e,w,e,st): 6}。

在第二轮中，我们看到 (e, st) 是最常见的字节对（计数为 9），我们会合并成 {(l,o,w): 5, (l,o,w,e,r): 2, (w,i,d,est): 3, (n,e,w,est): 6}。继续下去，我们最终得到的合并序列将是 ['s t', 'e st', 'o w', 'l ow', 'w est', 'ne', 'ne west', 'w i', 'wi d', 'wid est', 'low e', 'lowe r']。

如果我们进行 6 次合并，我们得到 ['s t', 'e st', 'o w', 'l ow', 'w est', 'n e']，我们的词汇表元素将是 [<|endoftext|>, [...256 BYTE CHARS], st, est, ow, low, west, ne]。

使用这个词汇表和合并集合，单词 newest 将被分词为 [ne, west]。

2.6 BPE 分词器：编码与解码

在作业的前一部分，我们实现了一个在输入文本上训练 BPE 分词器的函数，以获得分词器词汇表和 BPE 合并列表。现在，我们将实现一个 BPE 分词器，它加载给定的词汇表和合并列表，并用它们将文本编码为 token ID 以及将 token ID 解码为文本。

2.6.1 编码文本

通过 BPE 编码文本的过程与训练 BPE 词汇表的方式相似。主要有几个步骤。

步骤 1：预分词。我们首先对序列进行预分词，并将每个 pre-token 表示为一个 UTF-8 字节序列，正如 BPE 训练中所做的那样。我们将把每个 pre-token 内的这些字节合并为词汇表元素，独立处理每个 pre-token（不跨 pre-token 边界合并）。

步骤 2：应用合并。然后我们取 BPE 训练期间创建的词汇表元素合并序列，并按创建顺序将其应用到我们的 pre-token 上。

示例（bpe_encoding）：BPE 编码示例

例如，假设我们的输入字符串是 'the cat ate'，我们的词汇表是 {0: b' ', 1: b'a', 2: b'c', 3: b'e', 4: b'h', 5: b't', 6: b'th', 7: b' c', 8: b' a', 9: b'the', 10: b' at'}，我们学到的合并是 [(b't', b'h'), (b' ', b'c'), (b' ', b'a'), (b'th', b'e'), (b' a', b't')]。首先，我们的预分词器会把这个字符串切分为 ['the', ' cat', ' ate']。然后，我们查看每个 pre-token 并应用 BPE 合并。

第一个 pre-token 'the' 最初表示为 [b't', b'h', b'e']。查看我们的合并列表，我们识别出第一个可应用的合并是 (b't', b'h')，并用它将 pre-token 转换为 [b'th', b'e']。然后，我们回到合并列表，识别出下一个可应用的合并是 (b'th', b'e')，它将 pre-token 转换为 [b'the']。最后，再回头看合并列表，我们发现没有更多可应用于该字符串的合并了（因为整个 pre-token 已被合并为单个 token），于是我们完成了 BPE 合并的应用。对应的整数序列是 [9]。

对其余 pre-token 重复此过程，我们看到 pre-token ' cat' 在应用 BPE 合并后表示为 [b' c', b'a', b't']，对应整数序列 [7, 1, 5]。最后一个 pre-token ' ate' 在应用 BPE 合并后是 [b' at', b'e']，对应整数序列 [10, 3]。因此，编码输入字符串的最终结果是 [9, 7, 1, 5, 10, 3]。

特殊 token

你的分词器在编码文本时应能正确处理用户定义的特殊 token（在构造分词器时提供）。

内存方面的考虑

假设我们想对一个无法放入内存的大型文本文件进行分词。为了高效地对这个大文件（或任何其他数据流）进行分词，我们需要将其拆分为可管理的块并依次处理每个块，这样内存复杂度就是常数级别，而不是与文本大小成线性关系。这样做时，我们需要确保一个 token 不会跨越块边界，否则我们将得到与在内存中对整个序列分词的朴素方法不同的分词结果。

3 Transformer 语言模型架构

语言模型接收一个批量的整数 token ID 序列作为输入（即形状为 (batch_size, sequence_length) 的 torch.Tensor），并返回一个（批量的）词汇表上的归一化概率分布（即形状为 (batch_size, sequence_length, vocab_size) 的 PyTorch Tensor），其中预测的分布是针对每个输入 token 的下一个词。训练语言模型时，我们使用这些下一个词预测来计算实际下一个词与预测下一个词之间的交叉熵损失。推理时从语言模型生成文本时，我们取最后一个时间步（即序列中的最后一项）预测的下一个词分布来生成序列中的下一个 token（例如取概率最高的 token、从分布中采样等），将生成的 token 加到输入序列中，并重复此过程。

本部分作业中，你将从头构建这个 Transformer 语言模型。我们先对模型做一个高层描述，然后逐步细化各个组件。

3.1 Transformer LM

给定一个 token ID 序列，Transformer 语言模型使用输入嵌入（embedding）将 token ID 转换为稠密向量，将嵌入后的 token 通过 num_layers 个 Transformer 块，然后应用一个可学习的线性投影（「输出嵌入」或「LM head」）来产生预测的下一个 token logits。示意表示见图 1。

Token 嵌入

在第一步中，Transformer 将（批量的）token ID 序列嵌入为包含 token 身份信息的向量序列（图 1 中的红色块）。

更具体地说，给定一个 token ID 序列，Transformer 语言模型使用一个 token 嵌入层来产生一个向量序列。每个嵌入层接收形状为 (batch_size, sequence_length) 的整数张量，并产生形状为 (batch_size, sequence_length, d_model) 的向量序列。

Pre-norm Transformer 块

嵌入之后，激活值经过几个结构相同的神经网络层处理。一个标准的 decoder-only Transformer 语言模型由 num_layers 个相同的层组成（通常称为 Transformer「块」）。每个 Transformer 块接收形状为 (batch_size, sequence_length, d_model) 的输入，并返回形状为 (batch_size, sequence_length, d_model) 的输出。每个块通过自注意力（self-attention）聚合序列中的信息，并通过前馈层对其进行非线性变换。

经过 num_layers 个 Transformer 块之后，我们取最终的激活值，将其转换为词汇表上的分布。

我们将实现「pre-norm」Transformer 块（详见第 3.4 节），这还需要在最后一个 Transformer 块之后使用层归一化（详见下文）以确保其输出被适当地缩放。

在此归一化之后，我们将使用一个标准的可学习线性变换，将 Transformer 块的输出转换为预测的下一个 token logits（参见例如 [A. Radford et al. 7] 公式 2）。

3.2 说明：批处理、Einsum 与高效计算

在整个 Transformer 中，我们会对许多批处理式的输入执行相同的计算。以下是几个例子：

  • 批中的元素：我们对每个批元素应用相同的 Transformer 前向运算。
  • 序列长度：「按位置」（position-wise）的运算（如 RMSNorm 和前馈）对序列的每个位置执行完全相同的操作。
  • 注意力头：在多头（multi-headed）注意力运算中，注意力操作是在多个注意力头上进行批处理的。

拥有一种既能充分利用 GPU、又易于阅读和理解的方式来完成这些运算是很有用的。许多 PyTorch 运算可以在张量开头接受额外的「批处理式」维度，并高效地跨这些维度重复/广播该运算。

例如，假设我们正在做一个按位置、批处理的运算。我们有一个形状为 (batch_size, sequence_length, d_model) 的「数据张量」D，我们想对一个形状为 (d_model, d_model) 的矩阵 A 做批量向量-矩阵乘法。在这种情况下，D @ A 会进行批量矩阵乘法，这是 PyTorch 中的一个高效原语，其中 (batch_size, sequence_length) 维度被批处理。

正因如此，最好假设你的函数可能会被传入额外的批处理式维度，并将这些维度保持在 PyTorch 形状的开头。为了把张量组织成可以这样批处理的形式，它们可能需要通过多步 view、reshape 和 transpose 来整形。这可能有点麻烦，而且往往让人难以读懂代码在做什么、张量的形状是什么。

一个更符合人体工学的选择是使用 torch.einsum 中的 einsum 记号，或者使用 einops、einx 这类框架无关的库。两个关键运算是 einsum（可以对输入张量的任意维度做张量收缩）和 rearrange（可以对任意维度进行重排、拼接和拆分）。事实证明，机器学习中几乎所有的运算都是某种维度调整和张量收缩的组合，偶尔加上一个（通常是逐点的）非线性函数。这意味着使用 einsum 记号可以让你的大量代码更具可读性和灵活性。

我们强烈建议你学习并在本课程中使用 einsum 记号。以前没接触过 einsum 记号的同学应该使用 einops（文档见此处），而已经熟悉 einops 的同学应该学习更通用的 einx（见此处）。⁴ 这两个包都已经安装在我们提供的环境中。

⁴ 值得注意的是，虽然 einops 有大量支持，但 einx 还没有那么久经考验。如果你发现 einx 有任何限制或 bug，可以放心地回退到使用 einops 加一些更普通的 PyTorch。

下面我们给出一些 einsum 记号的使用示例。这些是对 einops 文档的补充，你应该先阅读 einops 文档。

示例（einstein_example1）：使用 einops.einsum 做批量矩阵乘法
import torch

from einops import rearrange, einsum

## 基础实现
Y = D @ A.T

# 很难看出输入和输出的形状以及它们的含义。
# D 和 A 可以有什么形状？其中哪些会有意外的行为？

## Einsum 是自文档化的、健壮的
# D A -> Y
Y = einsum(D, A, "batch sequence d_in, d_out d_in -> batch sequence d_out")

## 或者，一个批处理版本，其中 D 可以有任意前导维度，但 A 是受限的。
Y = einsum(D, A, "... d_in, d_out d_in -> ... d_out")
示例（einstein_example2）：使用 einops.rearrange 做广播运算

我们有一批图像，对于每张图像，我们要根据某个缩放因子生成 10 个变暗版本：

    "batch height width channel, dim_value -> batch dim_value height width channel"

示例（einstein_example3）：使用 einops.rearrange 做像素混合

假设我们有一批图像，表示为一个形状为 (batch, height, width, channel) 的张量，我们想对图像的所有像素执行线性变换，但该变换应对每个通道独立进行。我们的线性变换表示为一个形状为 (height * width, height * width) 的矩阵 B。

channels_last = torch.randn(64, 32, 32, 3)  # (batch, height, width, channel)

## 重排图像张量以在所有像素上混合
channels_last_flat = channels_last.view(-1, channels_last.size(1) * channels_last.size(2), channels_last.size(3))
channels_first_flat = channels_last_flat.transpose(1, 2)
channels_first_flat_transformed = channels_first_flat @ B.T
channels_last_flat_transformed = channels_first_flat_transformed.transpose(1, 2)
channels_last_transformed = channels_last_flat_transformed.view(*channels_last.shape)

改用 einops：

height = width = 32
## rearrange 取代了笨拙的 torch view + transpose
channels_first = rearrange(channels_last,
                                   "batch height width channel -> batch channel (height width)")
channels_first_transformed = einsum(channels_first, B,
                                   "batch channel pixel_in, pixel_out pixel_in -> batch channel pixel_out")
channels_last_transformed = rearrange(channels_first_transformed,
                                   "batch channel (height width) -> batch height width channel",
                                   height=height, width=width)

或者，如果你想来点疯狂的：用 einx.dot（einx 中相当于 einops.einsum 的东西）一步到位：

height = width = 32

                                   "batch row_in col_in channel, (row_out col_out) (row_in col_in) -> batch row_out col_out channel",
                                   channels_last, B,
                                   col_in=width, col_out=width)

Einsum 记号可以处理任意的输入批处理维度，同时还有一个关键好处——自文档化。在使用 einsum 记号的代码中，输入和输出张量的相关形状要清晰得多。对于其余张量，你可以考虑使用 Tensor 类型提示，例如使用 jaxtyping 库（并非 JAX 专用）。

3.2.1 数学记号与内存顺序

许多机器学习论文在记号中使用行向量，这样得到的表示与 NumPy 和 PyTorch 默认使用的行主序（row-major）内存顺序契合得很好。使用行向量时，线性变换看起来像

$$ \boldsymbol{y}=\boldsymbol{x}\boldsymbol{W}^\top, $$

其中 $W \in \mathbb{R}^{d_{\text{out}} \times d_{\text{in}}}$ 为行主序，$x \in \mathbb{R}^{1 \times d_{\text{in}}}$ 为行向量。注意，这让我们可以通过增大 $x$ 的最外层维度来批处理输入，也就是说我们可以把向量输入 $x$ 替换为矩阵输入 $X \in \mathbb{R}^{\text{batch} \times d_{\text{in}}}$。在线性代数中，更常见的是使用列向量，此时线性变换看起来像

$$ y=W x, $$

给定行主序的 $W \in \mathbb{R}^{d_{\text{out}} \times d_{\text{in}}}$ 和列向量 $x \in \mathbb{R}^{d_{\text{in}}}$。在这种设定下要批处理输入，$x$ 的批处理维度必须放在最后，因此 $x$ 需要被替换为一个矩阵 $\tilde{X} \in \mathbb{R}^{d_{\text{in}} \times \text{batch}}$。

本作业的数学记号将主要使用列向量，因为数学通常遵循这种记号。你应当记住：如果你想使用普通的矩阵乘法记号，就必须像公式 1 中行向量约定那样对矩阵做转置后再应用，因为 PyTorch 使用行主序内存顺序。如果你用 einsum 来做线性代数运算，那么只要你正确标注了轴，这就不成问题。顺带一提，值得注意 Matlab、Julia 和 Fortran 等其他语言/线性代数包都使用列主序（column-major）内存顺序，这意味着批处理维度放在最后，但 Python 及相关包采用了 C 标准的行主序。

3.4 Pre-Norm Transformer 块

每个 Transformer 块有两个子层：一个多头自注意力机制和一个按位置的前馈网络（[A. Vaswani et al., 2017]，第 3.1 节）。

在原始 Transformer 论文中，模型在两个子层的每一个周围使用残差连接，随后进行层归一化。这种架构通常被称为「post-norm」Transformer，因为层归一化应用于子层输出。然而，大量工作发现，将层归一化从每个子层的输出移到每个子层的输入（并在最后一个 Transformer 块之后额外做一次层归一化）可以提高 Transformer 训练稳定性 [T. Q. Nguyen et al., 2019; R. Xiong et al., 2020]——见「pre-norm」Transformer 块的可视化表示图 2。每个 Transformer 块子层的输出随后通过残差连接加到子层输入上（A. Vaswani et al. [8]，第 5.4 节）。对 pre-norm 的一种直觉理解是：从输入嵌入到 Transformer 最终输出之间存在一条没有任何归一化的干净「残差流」，据称这能改善梯度流动。这种 pre-norm Transformer 如今已成为语言模型的标准（例如 GPT-3、LLaMA、PaLM 等），因此我们将实现这一变体。我们将逐一讲解 pre-norm Transformer 块的各个组件，并按顺序实现它们。

3.4.1 Root Mean Square 层归一化

A. Vaswani et al. [8] 的原始 Transformer 实现使用层归一化 [J. L. Ba et al., 2016] 来归一化激活值。遵循 H. Touvron et al. [12]，我们将使用 root mean square 层归一化（RMSNorm；B. Zhang et al. [13]，公式 4）来进行层归一化。给定一个激活向量 $a \in \mathbb{R}^{d_{\text{model}}}$，RMSNorm 将按如下方式重新缩放每个激活值 $a_i$：

$$ \mathrm{RMSNorm}(a_i) = \frac{a_i}{\mathrm{RMS}(a)} g_i, $$

其中 $\mathrm{RMS}(a) = \sqrt{\frac{1}{d_{\mathrm{model}}} \sum_{i=1}^{d_{\mathrm{model}}} a_i^2 + \varepsilon}$。这里，$g_i$ 是一个可学习的「增益」（gain）参数（总共有 $d_{model}$ 个这样的参数），$\varepsilon$ 是一个通常固定为 $1e-5$ 的超参数。

你应该将输入上转型为 torch.float32，以防止对输入求平方时溢出。总的来说，你的 forward 方法应类似这样：

in_dtype = x.dtype
x = x.to(torch.float32)

# 在这里编写执行 RMSNorm 的代码
...
result = ...

# 以原始 dtype 返回结果
return result.to(in_dtype)

3.4.2 按位置的前馈网络（Position-Wise Feed-Forward Network）

在原始 Transformer 论文（A. Vaswani et al. [8] 第 3.3 节）中，Transformer 前馈网络由两个线性变换组成，中间有一个 ReLU 激活（$\mathrm{ReLU}(x) = \max(0, x)$）。在该原始架构中，内层前馈层的维度通常是输入维度的 4 倍。

然而，现代语言模型相比于这个原始设计倾向于引入两个主要变化：它们使用另一种激活函数，并采用一种门控机制。具体来说，我们将实现 Llama 3 [A. Grattafiori et al., 2024] 和 Qwen 2.5 [A. Yang et al., 2024] 等 LLM 采用的「SwiGLU」激活函数，它把 SiLU（常被称为 Swish）激活与一种称为门控线性单元（Gated Linear Unit，GLU）的门控机制结合起来。我们也将省略线性层中有时使用的偏置项，遵循自 PaLM [A. Chowdhery et al., 2022] 和 LLaMA [H. Touvron et al., 2023] 以来大多数现代 LLM 的做法。

SiLU 或 Swish 激活函数 [D. Hendrycks et al., 2016; S. Elfwing et al., 2017] 定义如下：

$$ \mathrm{SiLU}(x) = x \cdot \sigma(x) = \frac{x}{1 + e^{-x}} $$

如图 3 所示，SiLU 激活函数与 ReLU 激活函数相似，但在零点处是平滑的。

门控线性单元（GLU）最初由 Y. N. Dauphin et al. [19] 定义为一个经过 sigmoid 函数的线性变换与另一个线性变换的逐元素乘积：

$$ \mathrm{GLU}(x, W_1, W_2) = \sigma(W_1 x) \odot W_2 x, $$

其中 $\odot$ 表示逐元素乘法。门控线性单元被认为能够「通过为梯度提供线性路径、同时保留非线性能力，来缓解深层架构的梯度消失问题」。

将 SiLU/Swish 与 GLU 结合，我们得到 SwiGLU，它将用于我们的前馈网络：

$$ \mathrm{FFN}(x) = \mathrm{SwiGLU}(x, W_1, W_2, W_3) = W_2(\mathrm{SiLU}(W_1 x) \odot W_3 x), $$

其中 $x \in \mathbb{R}^{d_{\text{model}}}$，$W_1, W_3 \in \mathbb{R}^{d_{\text{ff}} \times d_{\text{model}}}$，$W_2 \in \mathbb{R}^{d_{\text{model}} \times d_{\text{ff}}}$，且按惯例 $d_{\text{ff}} = \frac{8}{3} d_{\text{model}}$。对于具体实现，为了硬件效率可以将其四舍五入到接近 64 的倍数。

N. Shazeer [20] 首先提出将 SiLU/Swish 激活与 GLU 结合，并进行了实验，表明 SwiGLU 在语言建模任务上优于 ReLU 和（无门控的）SiLU 等基线。稍后在本作业中，你将比较 SwiGLU 和 SiLU。尽管我们提到了这些组件的一些启发式论证（论文也提供了更多支持性证据），但保持经验主义的视角是好的：Shazeer 论文中有一句如今很出名的话是

「我们无法解释这些架构为何似乎有效；我们将其成功，如同其他一切一样，归因于神的仁慈。」

3.4.3 相对位置嵌入

为了向模型注入位置信息，我们将实现旋转位置嵌入（Rotary Position Embeddings，[J. Su et al., 2021]），通常称为 RoPE。对于 token 位置 $i$ 处的给定 query token $q^{(i)} = W_q x^{(i)} \in \mathbb{R}^d$，我们将应用一个成对的旋转矩阵 $R^i$，得到 $q'^{(i)} = R^i q^{(i)} = R^i W_q x^{(i)}$。这里，$R^i$ 将把嵌入元素对 $q^{(i)}_{2k-1:2k}$ 作为二维向量旋转角度 $\theta_{i,k} = \frac{i}{\Theta^{(2k-2)/d}}$，其中 $k \in \{1, ..., d/2\}$，$\Theta$ 为某个常数。因此，我们可以把 $R^i$ 视为一个大小为 $d \times d$ 的分块对角矩阵，块为 $R_k^i$（$k \in \{1, ..., \frac{d}{2}\}$），其中

$$ R_k^i = \begin{pmatrix} \cos(\theta_{i,k}) & -\sin(\theta_{i,k}) \\ \sin(\theta_{i,k}) & \cos(\theta_{i,k}) \end{pmatrix} $$

于是我们得到完整的旋转矩阵

$$ R^i = \begin{pmatrix} R_1^i & 0 & 0 & \cdots & 0 \\ 0 & R_2^i & 0 & \cdots & 0 \\ 0 & 0 & R_3^i & \cdots & 0 \\ \vdots & \vdots & \vdots & \ddots & \vdots \\ 0 & 0 & 0 & \cdots & R_{d/2}^i \end{pmatrix}, $$

其中 0 表示 $2 \times 2$ 的零矩阵。虽然可以构造完整的 $d \times d$ 矩阵，但一个好的解决方案应当利用该矩阵的性质来更高效地实现这个变换。由于我们只关心给定序列内 token 之间的相对旋转，我们可以跨层、跨不同批重用我们为 $\cos(\theta_{i,k})$ 和 $\sin(\theta_{i,k})$ 计算的值。如果你想优化，可以让所有层引用同一个 RoPE 模块，并在 init 期间用 self.register_buffer(persistent=False) 创建一个预计算的 sin 和 cos 值的二维缓冲区，而不是用 nn.Parameter（因为我们不想学习这些固定的余弦和正弦值）。我们对 $q^{(i)}$ 所做的完全相同的旋转过程随后也用于 $k^{(j)}$，用相应的 $R^j$ 进行旋转。注意，这一层没有可学习参数。

3.4.4 缩放点积注意力

现在我们将实现 A. Vaswani et al. [8]（第 3.2.1 节）中描述的缩放点积注意力（scaled dot-product attention）。作为预备步骤，Attention 运算的定义会用到 softmax，这是一个将一个未归一化的分数向量转换为归一化分布的运算：

$$ \mathrm{softmax}(v)_i = \frac{\exp(v_i)}{\sum_{j=1}^{n} \exp(v_j)}. $$

注意，当 $v_i$ 很大时 $\exp(v_i)$ 可能变成 $\inf$（此时 $\frac{\inf}{\inf} = \mathrm{NaN}$）。我们可以通过注意到 softmax 运算对给所有输入加上任意常数 $c$ 是不变的，来避免这一点。我们可以利用这一性质来保证数值稳定性——通常，我们从 $v$ 的所有元素中减去 $v$ 的最大元素，使新的最大元素变为 0。你现在将使用这个技巧来实现 softmax，以保证数值稳定性。

现在我们可以如下用数学方式定义 Attention 运算：

$$ \mathrm{Attention}(Q, K, V) = \mathrm{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V $$

其中 $Q \in \mathbb{R}^{n \times d_k}$，$K \in \mathbb{R}^{m \times d_k}$，$V \in \mathbb{R}^{m \times d_v}$。这里，$Q$、$K$ 和 $V$ 都是该运算的输入——注意这些不是可学习参数。

掩码（Masking）：有时对注意力运算的输出进行掩码会很方便。掩码应具有形状 $M \in \{\text{True}, \text{False}\}^{n \times m}$，这个布尔矩阵的每一行 $i$ 表示 query $i$ 应关注哪些 key。按惯例（并且略有些令人困惑），位置 $(i,j)$ 处的值为 $\text{True}$ 表示 query $i$ 确实关注 key $j$，值为 $\text{False}$ 表示该 query 不关注该 key。换句话说，在值为 $\text{True}$ 的 $(i,j)$ 对上「信息会流动」。例如，考虑一个条目为 $[[\text{True}, \text{True}, \text{False}]]$ 的 $1 \times 3$ 掩码矩阵。这单个 query 向量只关注前两个 key。

从计算上讲，使用掩码比在子序列上计算注意力要高效得多，我们可以通过取 softmax 之前的值 $(QK^{\top}/\sqrt{d_k})$，并在掩码矩阵中为 $\text{False}$ 的任何条目上加上 $-\infty$ 来实现这一点。

3.4.5 因果多头自注意力

我们将实现 A. Vaswani et al. [8] 第 3.2.2 节中描述的多头自注意力。回顾一下，从数学上讲，应用多头注意力的运算定义如下：

$$ \mathrm{MultiHead}(Q, K, V) = \mathrm{Concat}(\mathrm{head}_1, ..., \mathrm{head}_h) $$

其中 $\mathrm{head}_i = \mathrm{Attention}(Q_i, K_i, V_i)$，

$Q_i$、$K_i$、$V_i$ 分别是 $Q$、$K$、$V$ 的嵌入维度上大小为 $d_k$ 或 $d_v$ 的第 $i \in \{1, ..., h\}$ 个切片。Attention 是第 3.4.4 节中定义的缩放点积注意力运算。由此我们可以形成多头自注意力运算：

$$ \mathrm{MultiHeadSelfAttention}(x) = W_O \mathrm{MultiHead}(W_Q x, W_K x, W_V x) $$

这里，可学习参数是 $W_Q \in \mathbb{R}^{hd_k \times d_{\text{model}}}$、$W_K \in \mathbb{R}^{hd_k \times d_{\text{model}}}$、$W_V \in \mathbb{R}^{hd_v \times d_{\text{model}}}$ 和 $W_O \in \mathbb{R}^{d_{\text{model}} \times h d_v}$。由于 Q、K、V 在多头注意力运算中被切片，我们可以把 $W_Q$、$W_K$ 和 $W_V$ 看作沿输出维度为每个头分离。当你把这个做对之后，你应该总共用三次矩阵乘法来计算 key、value 和 query 投影。⁵

⁵ 作为一个进阶目标，尝试把 key、query 和 value 投影合并到一个权重矩阵中，这样你只需要一次矩阵乘法。
因果掩码

你的实现应防止模型关注序列中的未来 token。换句话说，如果给模型一个 token 序列 $t_1, ..., t_n$，我们想计算前缀 $t_1, ..., t_i$（其中 $i < n$）的下一个词预测，模型不应能够访问（关注）位置 $t_{i+1}, ..., t_n$ 处的 token 表示，因为它在推理时生成文本时无法访问这些 token（而且这些未来 token 会泄露真实下一个词身份的信息，使语言建模预训练目标变得平凡）。对于输入 token 序列 $t_1, ..., t_n$，我们可以通过运行 $n$ 次多头自注意力（对应序列中的 $n$ 个唯一前缀）来朴素地阻止对未来 token 的访问。相反，我们将使用因果注意力掩码，它允许 token $i$ 关注序列中所有满足 $j \leq i$ 的位置 $j$。你可以使用 torch.triu 或广播的索引比较来构造这个掩码，并且应利用你从第 3.4.4 节实现的缩放点积注意力已经支持注意力掩码这一事实。

应用 RoPE

RoPE 应应用于 query 和 key 向量，但不应用于 value 向量。此外，头的维度应作为批处理维度处理，因为在多头注意力中，注意力是对每个头独立应用的。这意味着完全相同的 RoPE 旋转应应用于每个头的 query 和 key 向量。

4.1 交叉熵损失

回顾一下，Transformer 语言模型为每个长度为 $m+1$ 的序列 x 以及 $i=1,...,m$ 定义一个分布 $p_{\theta}(x_{i+1} \mid x_{1:i})$。给定一个由长度为 $m+1$ 的序列组成的训练集 D，我们定义标准的交叉熵（负对数似然）损失函数：

$$ \ell(\theta; D) = \frac{1}{|D| m} \sum_{x \in D} \sum_{i=1}^{m} -\log p_{\theta}(x_{i+1} | x_{1:i}). $$

（注意，Transformer 中的一次前向传播会为所有 $i = 1, ..., m$ 产生 $p_{\theta}(x_{i+1} \mid x_{1:i})$。）

特别地，Transformer 为每个位置 $i$ 计算 logits $o_i \in \mathbb{R}^{\text{vocab\_size}}$，从而得到：⁶

$$ p(x_{i+1} | x_{1:i}) = \mathrm{softmax}(o_i)[x_{i+1}] = \frac{\exp(o_i[x_{i+1}])}{\sum_{a=1}^{\text{vocab\_size}} \exp(o_i[a])}. $$

交叉熵损失通常相对于 logits 向量 $o_i \in \mathbb{R}^{\text{vocab\_size}}$ 和目标 $x_{i+1}$ 来定义。⁷

⁶ 注意，$o_i[k]$ 指的是向量 $o_i$ 中索引 $k$ 处的值。⁷ 这对应于 $x_{i+1}$ 上的 Dirac delta 分布与预测的 $\mathrm{softmax}(o_i)$ 分布之间的交叉熵。

实现交叉熵损失需要像 softmax 一样小心处理数值问题。

4.2 SGD 优化器

现在我们有了损失函数，将开始探索优化器。最简单的基于梯度的优化器是随机梯度下降（Stochastic Gradient Descent，SGD）。我们从随机初始化的参数 $\theta_0$ 开始。然后对于每一步 $t = 0, ..., T - 1$，我们执行以下更新：

$$ \theta_{t+1} \leftarrow \theta_t - \alpha_t \nabla L(\theta_t; B_t), $$

其中 $B_t$ 是从数据集 D 中采样的一批随机数据，学习率 $\alpha_t$ 和批量大小 $|B_t|$ 是超参数。

4.2.1 在 PyTorch 中实现 SGD

要实现我们的优化器，我们将继承 PyTorch 的 torch.optim.Optimizer 类。一个 Optimizer 子类必须实现两个方法：

def __init__(self, params, ...) —— 应初始化你的优化器。这里，params 是要优化的参数集合（或参数组，以防用户想对模型的不同部分使用不同的超参数，例如不同的学习率）。务必将 params 传给基类的 __init__ 方法，基类会存储这些参数供 step 使用。你可以根据优化器接受额外参数（学习率是常见的一个），并把它们作为字典传给基类构造函数，其中键是你为这些参数选择的名字（字符串）。

def step(self) —— 应对参数做一次更新。在训练循环中，它会在反向传播之后被调用，因此你可以访问最后一批数据的梯度。此方法应遍历每个参数张量 p，并基于梯度 p.grad（如果存在的话，它是损失相对于该参数的梯度张量）就地修改它们，即设置 p.data（p.data 保存与该参数关联的张量）。

PyTorch 优化器 API 有一些微妙之处，所以用例子来解释更容易。为了让例子更丰富，我们将实现 SGD 的一个轻微变体，其中学习率随训练衰减，从一个初始学习率 $\alpha$ 开始，随时间采取越来越小的步长：

$$ \theta_{t+1} = \theta_t - \frac{\alpha}{\sqrt{t+1}} \nabla L(\theta_t; B_t) $$

让我们看看这个 SGD 变体会如何作为 PyTorch Optimizer 实现：

from collections.abc import Callable, Iterable
from typing import Optional
import torch
import math

class SGD(torch.optim.Optimizer):
    def __init__(self, params, lr=1e-3):
        if lr < 0:
            raise ValueError(f"Invalid learning rate: {lr}")
        defaults = {"lr": lr}
        super().__init__(params, defaults)

    def step(self, closure: Optional[Callable] = None):
        loss = None if closure is None else closure()
        for group in self.param_groups:
            lr = group["lr"]  # 获取学习率。
            for p in group["params"]:
                if p.grad is None:
                    continue
                state = self.state[p]  # 获取与 p 关联的状态。
                t = state.get("t", 0)  # 从状态中获取迭代次数，或 0。
                grad = p.grad.data  # 获取损失相对于 p 的梯度。
                p.data -= lr / math.sqrt(t + 1) * grad  # 就地更新权重张量。
                state["t"] = t + 1  # 递增迭代次数。
        return loss

在 __init__ 中，我们把参数以及默认超参数传给基类构造函数（参数可能以组的形式出现，每组有不同的超参数）。如果参数只是单个 torch.nn.Parameter 对象集合，基类构造函数会创建单个组并给它分配默认超参数。然后，在 step 中，我们遍历每个参数组，再遍历该组中的每个参数，并应用公式 20。这里，我们把迭代次数保存为与每个参数关联的状态：我们先读取这个值，在梯度更新中使用它，然后再更新它。API 规定用户可以传入一个可调用的 closure，在优化器步进之前重新计算损失。对于我们使用的优化器，我们不需要这个，但为了符合 API 我们加上它。

要看到它的工作效果，我们可以使用下面这个最小的训练循环示例：

weights = torch.nn.Parameter(5 * torch.randn((10, 10)))
opt = SGD([weights], lr=1)

for t in range(100):
    opt.zero_grad()  # 重置所有可学习参数的梯度。
    loss = (weights**2).mean()  # 计算一个标量损失值。
    print(loss.cpu().item())

    loss.backward()  # 运行反向传播，计算梯度。
    opt.step()  # 运行优化器步进。

这是训练循环的典型结构：在每次迭代中，我们计算损失并运行一步优化器。训练语言模型时，我们的可学习参数来自模型（在 PyTorch 中，m.parameters() 给了我们这个集合）。损失将在一批采样数据上计算，但训练循环的基本结构是相同的。

4.3 AdamW

现代语言模型通常用比 SGD 更复杂的优化器训练。最近使用的大多数优化器都是 Adam 优化器 [D. P. Kingma et al., 2015] 的衍生物。我们将使用 AdamW [Loshchilov et al., 2019]，它在近期工作中被广泛使用。AdamW 对 Adam 提出一个修改，通过加入权重衰减（每次迭代把参数拉向 0）来改善正则化，其方式与梯度更新解耦。我们将按 [Loshchilov et al., 2019] 的算法 2 中所述实现 AdamW。

AdamW 是有状态的：对每个参数，它跟踪其一阶矩和二阶矩的运行估计。因此，AdamW 以额外内存换取改进的稳定性和收敛性。除了学习率 $\alpha$，AdamW 还有一对控制矩估计更新的超参数 $(\beta_1, \beta_2)$，以及一个权重衰减率 $\lambda$。典型应用把 $(\beta_1, \beta_2)$ 设为 $(0.9, 0.999)$，但像 LLaMA [H. Touvron et al., 2023] 和 GPT-3 [T. B. Brown et al., 2020] 这样的大型语言模型通常用 $(0.9, 0.95)$ 训练。算法可以写成如下形式，其中 $\varepsilon$ 是一个小值（例如 $10^{-8}$），用于在 $v$ 中出现极小值时改善数值稳定性：

算法 1：AdamW 优化器

1   init(θ)                                     ▷ 初始化可学习参数
2   m ← 0                                       ▷ 一阶矩向量初始值；与 θ 形状相同
3   v ← 0                                       ▷ 二阶矩向量初始值；与 θ 形状相同
4   for t = 1, ..., T do
5       采样一批数据 B_t
6       g ← ∇_θ ℓ(θ; B_t)                       ▷ 计算损失的梯度
7       α_t ← α · sqrt(1 - β_2^t) / (1 - β_1^t) ▷ 计算第 t 次迭代调整后的 α
8       θ ← θ - α λ θ                           ▷ 应用权重衰减
9       m ← β_1 m + (1 - β_1) g                 ▷ 更新一阶矩估计
10      v ← β_2 v + (1 - β_2) g^2               ▷ 更新二阶矩估计
11      θ ← θ - α_t · m / (sqrt(v) + ε)         ▷ 应用经矩调整的权重更新
12  end for
算法 1：AdamW 优化器伪代码。

注意 t 从 1 开始。你现在将实现这个优化器。

4.4 学习率调度

使损失最快下降的学习率值在训练过程中往往会变化。在训练 Transformer 时，通常使用学习率调度（schedule），我们从较大的学习率开始，在开始时进行更快的更新，并随着模型训练缓慢衰减到较小的值。⁸

⁸ 有时也常见使用一种学习率回升（restart）的调度，以帮助越过局部极小值。 在本作业中，我们将实现训练 LLaMA [H. Touvron et al., 2023] 所用的余弦退火（cosine annealing）调度。

调度器只是一个函数，它接收当前步 t 和其他相关参数（例如初始和最终学习率），并返回在第 t 步的梯度更新中要使用的学习率。最简单的调度是常函数，它对于任何 t 都返回相同的学习率。

余弦退火学习率调度接收：(i) 当前迭代 t，(ii) 最大学习率 $\alpha_{\max}$，(iii) 最小（最终）学习率 $\alpha_{\min}$，(iv) 预热（warm-up）迭代次数 $T_w$，以及 (v) 余弦退火的最终迭代 $T_c$。第 t 次迭代的学习率定义为：

（预热）若 $t < T_w$，则 $\alpha_t = \frac{t}{T_w} \alpha_{\max}$。

（余弦退火）若 $T_w \leq t \leq T_c$，则 $\alpha_t = \alpha_{\min} + \frac{1}{2} \left(1 + \cos\left(\frac{t - T_w}{T_c - T_w} \pi\right)\right) (\alpha_{\max} - \alpha_{\min})$。

（退火之后）若 $t > T_c$，则 $\alpha_t = \alpha_{\min}$。

4.5 梯度裁剪

在训练期间，我们有时会遇到产生大梯度的训练样本，这会破坏训练的稳定性。为了缓解这一点，实践中常用的一种技术是梯度裁剪。其思想是在每次反向传播之后、执行优化器步进之前，对梯度的范数施加一个限制。

给定（所有参数的）梯度 $g$，我们计算它的 $\ell_2$-范数 $\|g\|_2$。如果这个范数小于最大值 $M$，则保持 $g$ 不变；否则，我们把 $g$ 按因子 $\frac{M}{\|g\|_2 + \varepsilon}$ 缩小（其中为了数值稳定性加一个小的 $\varepsilon$，如 $10^{-6}$）。注意，得到的范数会略小于 $M$。

5.1 数据加载器

分词后的数据（例如你在 tokenizer_experiments 中准备的数据）是一个单一的 token 序列 $x = (x_1, ..., x_n)$。尽管源数据可能由独立的文档组成（例如不同的网页或源代码文件），常见的做法是把它们全部连接成一个单一的 token 序列，在它们之间加入一个分隔符（例如 <|endoftext|> token）。

数据加载器把它转换为一批批（batch）的流，其中每个批由 $B$ 个长度为 $m$ 的序列组成，并与对应的长度为 $m$ 的下一个 token 配对。例如，对于 $B=1, m=3$，$([x_2, x_3, x_4], [x_3, x_4, x_5])$ 就是一个可能的批。

以这种方式加载数据简化了训练，原因有几个。首先，任何 $1 \leq i \leq n - m$ 都给出一个有效的训练序列，所以采样训练序列是平凡的。由于所有训练序列长度相同，无需对输入序列进行填充，这提高了硬件利用率（也通过增大批量大小 $B$）。最后，我们也不需要加载完整数据集来采样训练数据，从而更容易处理那些否则可能无法放入内存的大型数据集。

除了加载数据，我们还需要在训练时保存模型。运行作业时，我们通常希望能够恢复一个中途停止的训练运行（例如因为你的作业超时、机器故障等）。即使一切顺利，我们也可能希望稍后能访问中间模型（例如事后研究训练动态、从不同训练阶段的模型采样等）。

6 生成文本

现在我们可以训练模型了，我们需要的最后一块是能够从模型生成文本。回顾一下，语言模型接收一个（可能批处理的）长度为 sequence_length 的整数序列，并产生一个大小为 (sequence_length, vocab_size) 的矩阵，其中序列的每个元素都是一个预测该位置之后下一个 token 的概率分布。现在我们将编写几个函数，把它转化为新序列的采样方案。

Softmax

按标准约定，语言模型的输出是最后一个线性层的输出（「logits」），所以我们必须通过 softmax 运算把它转化为归一化概率，正如我们之前在公式 10 中看到的那样。

解码

要从我们的模型生成文本（解码），我们给模型一个前缀 token 序列（「prompt」），让它产生一个预测序列中下一个 token 的、词汇表上的概率分布。然后，我们从这个词汇表项上的分布采样，来确定下一个输出 token。

具体来说，解码过程的一步应接收一个序列 $x_{1...t}$，并通过下面的公式返回一个 token $x_{t+1}$：

$$ P(x_{t+1}=i \mid x_{1...t}) = \frac{\exp(v_i)}{\sum_j \exp(v_j)} $$
$$ v = \mathrm{TransformerLM}(x_{1...t})_t \in \mathbb{R}^{\text{vocab\_size}} $$

其中 TransformerLM 是我们的模型，它接收长度为 sequence_length 的序列作为输入，并产生大小为 (sequence_length, vocab_size) 的矩阵，我们取这个矩阵的最后一个元素，因为我们要找的是第 t 个位置的下一个 token 预测。

这给了我们一个基本的解码器：反复从这些单步条件分布中采样（把我们之前生成的输出 token 追加到下一个解码时间步的输入），直到我们生成序列结束 token <|endoftext|>（或达到用户指定的最大生成 token 数）。

解码器技巧

我们将用小模型做实验，而小模型有时会生成质量很低的文本。两个简单的解码器技巧可以帮助解决这些问题。首先，在温度缩放（temperature scaling）中，我们用温度参数 $\tau$ 修改我们的 softmax，新的 softmax 为

$$ \mathrm{softmax}(v, \tau)_i = \frac{\exp(v_i/\tau)}{\sum_{j=1}^{\text{vocab\_size}} \exp(v_j/\tau)}. $$

注意，令 $\tau \to 0$ 会使 v 的最大元素占据主导，softmax 的输出变成一个集中在该最大元素上的 one-hot 向量。

其次，另一个技巧是核采样（nucleus）或 top-p 采样，我们通过截断低概率 token 来修改采样分布。设 q 是我们从（经过温度缩放的）大小为 vocab_size 的 softmax 得到的概率分布。超参数为 p 的核采样按下式产生下一个 token：

$$ P(x_{t+1}=i \mid q) = \begin{cases} \frac{q_i}{\sum_{j \in V(p)} q_j} & \text{若 } i \in V(p) \\ 0 & \text{否则} \end{cases} $$

其中 $V(p)$ 是满足 $\sum_{j \in V(p)} q_j \geq p$ 的最小索引集合。你可以通过先把概率分布 q 按大小排序，然后选择最大的词汇表元素直到达到目标水平 p，来轻松计算这个量。

现在让我们研究另一个乍一看很随意的层归一化选择。Pre-norm Transformer 块定义为

$$ z = x + \mathrm{MultiHeadSelfAttention}(\mathrm{RMSNorm}(x)) $$
$$ y = z + \mathrm{FFN}(\mathrm{RMSNorm}(z)). $$

这是对原始 Transformer 架构为数不多的「共识性」修改之一，原始架构使用 post-norm 方式：

$$ z = \mathrm{RMSNorm}(x + \mathrm{MultiHeadSelfAttention}(x)) $$
$$ y = \mathrm{RMSNorm}(z + \mathrm{FFN}(z)). $$

让我们改回 post-norm 方式，看看会发生什么。

我们看到层归一化对 Transformer 的行为有重大影响，而且即使层归一化的位置也很重要。

消融 2：位置嵌入

接下来我们将研究位置嵌入对模型性能的影响。具体来说，我们将比较我们的基础模型（带 RoPE）与完全不包含位置嵌入（NoPE）的情况。事实证明，decoder-only Transformer（即像我们实现的那样带因果掩码的 Transformer）理论上可以在不显式提供位置嵌入的情况下推断出相对或绝对位置信息 [Y.-H. H. Tsai et al., 2019; A. Kazemnejad et al., 2023]。现在我们将实证测试 NoPE 与 RoPE 相比表现如何。

消融 3：SwiGLU vs. SiLU

接下来，我们将遵循 [N. Shazeer 20]，通过比较 SwiGLU 前馈网络与使用 SiLU 激活但无门控线性单元（GLU）的前馈网络的性能，来测试前馈网络中门控的重要性：

$$ \mathrm{FFN}_{\mathrm{SiLU}}(x) = W_2 \mathrm{SiLU}(W_1 x). $$

回顾一下，在我们的 SwiGLU 实现中，我们把内层前馈层的维度设为大约 $d_{ff} = \frac{8}{3}d_{model}$（同时确保 $d_{ff} \mod 64 = 0$，以利用 GPU tensor core）。在这个消融基线中，你的 FFN$_{SiLU}$ 实现应改为设 $d_{ff} = 4 \times d_{model}$，以大致匹配默认 SwiGLU 前馈网络的参数数量（它有三个而非两个权重矩阵）。
